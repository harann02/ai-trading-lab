# Forward Trading Verification

Purpose: prove the *operation* (not the profitability) of v3 over **20 consecutive unattended US sessions** (GitHub schedule or external backup cron, labelled per session).

* **Start session:** first NYSE session whose open is after the v3 migration timestamp (`ledger_meta.v3_applied_ts`). Nothing before it counts. Tests, demo data and manual runs without a real GitHub run id never count.
* **15 recorded items per session:** scan occurred, data retrieved, stocks evaluated, candidates, passed risk, proposed, submitted, rejected, filled, positions reconciled, P&L correct (ledger identity checks), daily report generated, errors, stale feeds, missed runs.
* **A session QUALIFIES** if: the EOD scan ran from an unattended trigger (github-schedule or external-backup; success, real run id, started inside the EOD window [NYSE close + 30 min, next open) — the first unattended run in that window is the on-time scan; a catch-up scan (window lapsed) or a scan before close + 30 min does *not* qualify; the 15 Oct 2026 session is left failed for that reason, see SCHEDULER.md), data retrieved, stocks evaluated > 0, positions reconciled, P&L identity ok, daily report stored, 0 errors, 0 stale feeds, monitor coverage ≥ 75 % of expected 15-min slots and no gap > 120 min. **A session with no trades qualifies** if every check completed (cash is a valid decision).
* A session with no evidence by the next open is **FAILED (missed run)**.
* **Statuses:** NOT STARTED · IN PROGRESS · ACTION REQUIRED (latest completed session failed; streak resets) · FAILED (≥ 3 failed sessions) · **OPERATIONALLY VERIFIED** only with ≥ 20 consecutive QUALIFIED sessions (enforced in code; tests prove 19 ≠ verified).
* **Unattended runs that COUNT (user-approved 2026-10-15):** (1) GitHub cron, event `schedule`, labelled **`github-schedule`**; (2) the external backup cron (cron-job.org → `repository_dispatch` type `external-cron`, trigger class `external_scheduler`, see `docs/EXTERNAL_CRON.md`), labelled **`external-backup`**. Both satisfy "scan occurred on schedule" and both count toward monitor coverage and the 20-session streak. Every session records `scan_source` (`github-schedule`, `external-backup` or `external-backup+github-schedule`) and `monitor_runs_by_source`; `verification.summary()` exposes `source_breakdown` (runs and scan sessions per source, qualifying sessions by scan source) plus `unattended_runs_recorded`. The dashboard Verification tab shows the breakdown and a per-session "scan source" / "monitors (gh / ext)" column.
* **Never counted:** manual `workflow_dispatch` and `push` runs (listed separately as "Manual / push runs"), and anything without a real GitHub run id.
* Computed by `app/v3/verification.py` on every persisted run; shown on Overview (card "FORWARD TRADING VERIFICATION") and the Verification tab. Honest state at v3 launch: **0 of 20**.
