# Experiment & change process
No live parameter changes automatically. Weekly evaluation (`weekly_eval`) produces **proposals only** (status PROPOSED).
A change proposal must pass, in order: (1) pre-declared hypothesis and decision rule; (2) train / validation / **holdout** split fixed in advance (holdout touched once); (3) walk-forward windows; (4) cost sensitivity (×1/×2/×3 modelled spread+slippage); (5) parameter stability (±1 step must not flip the conclusion); (6) regime breakdown (calendar-year windows); (7) minimum sample (≥ 30 trades); (8) **owner authorization** via the Controls path (settings are validated + audited). Strategy versions are preserved (`algo_version` on every decision; `validation/` results are committed, never overwritten silently). Optimized backtests are never presented as independent validation; survivorship bias and missing point-in-time fundamentals remain (see VALIDATION.md).
Mean-reversion reactivation additionally needs the validation conditions in `app/v3/policy.py::REACTIVATION_RULES` **and** the exact confirmation text (`REACTIVATE meanrev`); there is no auto-reactivation.
